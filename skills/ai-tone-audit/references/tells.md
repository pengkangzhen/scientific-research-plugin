# 中文学术写作 AI 腔病理分类与处置细则（Z1–Z12）

> 词表与正则只是初筛网，不是判决书。单个词在人类论文里同样会出现；AI 腔的本质是**高概率安全套话的密集聚集 + 具体事实缺位 + 句法节奏均质化**。审计员必须读前后 2–3 句上下文再下判定。

## 一、十二类病理总表

| 类 | 名称 | 典型形态 | 默认处置 | 常见合法情形（防误报） |
|---|---|---|---|---|
| **Z1** | 宏大开篇与空洞铺垫 | 「随着……的快速发展」「在……大背景下」「近年来……日益成为研究热点」「众所周知」 | **删** 或 **实** | 全文引言首句若有具体年份/规模/政策文号支撑的「近年来」，保留事实、剥掉套壳 |
| **Z2** | 讲义腔路标词（过度显化） | 「值得注意的是」「需要指出的是」「不难发现」「毋庸置疑」；正文段内滥用「综上所述/由此可见」；段段「此外，……与此同时，……」 | **删** | 「本章小结 / 结论」节内的单次总结词；定理/引理后确有反直觉边界需提醒读者的单处「需注意」 |
| **Z3** | 拔高套话与公文/营销腔 | 「具有重要的理论与现实意义」「为……提供了新思路/有力支撑」「奠定了坚实基础」「至关重要」「扮演着……角色」「赋能/抓手/闭环/底层逻辑/全方位/多维度/全新范式」 | **删** 或 **实** | 基金本子「研究意义」小节允许交代应用价值，但仍须落地到具体场景、指标或决策主体，禁空喊口号 |
| **Z4** | 二分对照壳（否定式平行） | 「不是简单的 A，而是一种全新的 B」「与其说是……不如说是……」「不仅仅是……更是……」「不仅……而且……」密集连用 | **改** | 全文偶发 1 次、用于界定真实概念边界（如区分鲁棒优化与随机规划假设）的「不是……而是……」 |
| **Z5** | 四字格机械连排 | 「降本增效、提质升级、协同创新和绿色低碳」「互联互通、共建共享、深度融合」 | **删** 或 **改** | **领域标准术语枚举**（如「整数规划、动态规划与鲁棒优化」「精确算法、启发式算法和元启发式算法」）→ 判 **留** |
| **Z6** | 机械枚举外壳 | 非步骤论述段落套用「首先，……；其次，……；最后，……」「第一，……第二，……第三，……」 | **改** | **算法流程、实验步骤、定理证明分情形、贡献点显式编号** → 判 **留** |
| **Z7** | 段末升华与挑战展望尾巴 | 多句段落末尾必挂「由此可见，……」「这充分表明……」「尽管仍面临诸多挑战，但未来前景广阔」 | **删** | 独立「结论与展望」末段的收束句（仍须指向具体未解问题，而非「未来可期」） |
| **Z8** | 欧化弱动词与翻译腔 | 「对……进行了系统分析」「实现了求解效率的提升」「模型的有效性得到了验证」「通过……，使得……」主语残缺；三层以上「的」字链 | **改** | 固定学科搭配（如「进行敏感性分析」偶发出现且全段动词不单调时可放行） |
| **Z9** | 抽象施事（虚假主语） | 「实验结果深刻揭示了/彰显了……」「本框架致力于……」「本研究的开展……」 | **改** | 常规平实陈述如「表 3 显示」「图 4 给出」「实验结果表明 + 具体数值结论」不判病 |
| **Z10** | 空泛评价（无数字断言） | 句内无任何数字/公式/图表引用，却断言「显著提升了效率」「展现出了优异的性能」「有效解决了复杂问题」 | **实** | 摘要首句或章节导语紧跟下文具体实验表（且同段后句即给出数字）时，可合并两句而非强插占位符 |
| **Z11** | 格式排版癖 | 正文叙述段频繁 `——` 破折号解释、段内到处 `\textbf{}` / `**加粗**` 关键词、把普通段落拆成「**小标题：** 一句话」清单 | **改** | 定义环境首次引入核心术语加粗；数学符号或破折号偶发规范使用 |
| **Z12** | 节奏单调与段落同构 | 整节句长变异系数 `CV < 0.35`（句句 22–28 字节拍器式推进）；连续 4 段以上字数与「观点+解释+升华」结构完全同构 | **改** | 纯符号定义节、参数说明节（天生句式规整）→ 判 **留** |
| **R** | 跨技能转交项 | 同句堆叠 ≥2 个对冲词（「可能在一定程度上或许……」）；Results 段末免责退路；AI 自造复合名词黑话 | **转** | 转交 `hedge-audit`（防御性写作）或 `term-audit` / `jargon-check`（术语黑话），本技能不重复判罚 |

## 二、五档处置动作与硬红线

Stage 2 审计对每处有效问题只给以下五档处置之一：

1. **删（DELETE）**：剥离零信息填充词、空洞背景铺垫、段末升华尾巴。判准：**删掉后，句子的事实命题与逻辑衔接不损失任何信息**。
2. **实（CONCRETIZE）**：把空泛形容词/拔高套话替换为手稿中**已经存在**的具体数字、算例规模、求解时间、对比基准、政策文号或机理名称。
   - **反编造铁律**：若通读手稿上下文找不到对应事实支撑，**严禁模型自行编造数字、百分比、文献或案例**，一律写成显式槽位 `⟨作者补：具体比例/算例规模/对比基准⟩`，并在报告末尾列入「需作者补充的事实清单」。
3. **改（RESTRUCTURE）**：重写句法外壳但保留全部事实命题：
   - 弱动词还原为强动词：「对文献进行了系统梳理」→「梳理了……文献」；「模型的有效性得到了验证」→「算例验证了模型有效」。
   - 补回缺失主语：「通过引入拉格朗日松弛，使得下界质量提高」→「引入拉格朗日松弛后，下界间隙缩小了 ⟨X⟩%」（或「拉格朗日松弛提高了下界质量」）。
   - 拆解二分对照壳与同构长句：把「不是……而是……」「不仅……而且……」改成直陈句；在 25 字均质句群中穿插短判断句（8–15 字）与带数据的长句，拉开节奏。
4. **留（KEEP）**：属于上表「合法情形」的初筛命中，明确标 **留** 并附一句理由（防过度审计误伤正常学术表达）。
5. **转（ROUTE）**：属于防御性让步/退路从句 → 标 `转 hedge-audit`；属于可疑自造复合术语或全稿术语不一致 → 标 `转 term-audit`。

> **同义词替换禁令**：严禁把「至关重要」换成「极为关键」、把「值得注意的是」换成「应当看到」、把「赋能」换成「助力」。同义替换只是把显眼套话换成次显眼套话，Stage 3 回归扫描会直接拦截。

## 三、中文学术改写对照样例

### 样例 1：引言背景段（Z1 + Z3 + Z10 → 删 + 实）

- **原稿**：随着全球贸易的快速发展，集装箱航运在国际物流体系中扮演着至关重要的角色。近年来，港口拥堵问题日益凸显，已成为学术界和业界关注的焦点。在此背景下，如何有效提升港口作业效率，具有重要的理论意义和现实价值。
- **问题诊断**：3 句 98 字，包含 Z1×4、Z3×4、Z10×1，有效学科信息几乎为零——任何港航论文都能原封不动套用。
- **改写方向**：
  > 2021—2023 年间，全球前 20 大集装箱港口的平均船舶待泊时间由 ⟨作者补：基准小时数⟩ 上升至 ⟨作者补：峰值小时数⟩ \cite{⟨key⟩}。待泊延误沿班轮干线向后续挂靠港传导，推高了船公司的燃油与租船成本。本文研究不确定到港时间下的泊位—堆场联合调度问题，目标是最小化总在港时间。

### 样例 2：方法与文献过渡段（Z2 + Z4 + Z8 + Z9 → 删 + 改）

- **原稿**：值得注意的是，现有研究不仅忽视了泊位与堆场的耦合关系，而且缺乏对到港不确定性的系统刻画。本文致力于构建一个全方位、多维度的优化框架，对上述问题进行深入研究，这不是简单的参数调整，而是一种全新的建模范式。
- **改写方向**：
  > 现有研究大多分开求解泊位分配与堆场箱位计划，或将随机到港时间简化为确定性均值。本文将泊位分配与堆场龙门吊调度纳入同一两阶段随机整数规划，用经验分布刻画船舶到港延误，并在耦合约束中显式计入水平运输拥堵。

### 样例 3：实验结果段（Z6 + Z8 + Z9 + Z10 + Z7 → 实 + 改 + 删）

- **原稿**：首先，本文对小规模算例进行了求解验证；其次，对大规模算例进行了对比实验；最后，通过敏感性分析，使得算法的鲁棒性得到了充分验证。实验结果深刻揭示了所提方法的优越性能，显著提升了求解效率，由此可见，该方法具有广阔的应用前景。
- **改写方向**（假设手稿表 4 已有数据）：
  > 表 4 对比了小规模（20 艘船）与大规模（150 艘船）算例的求解表现。在 20 艘船算例上，分支定价算法与 Gurobi 均求得最优解，平均耗时分别为 18.4 秒与 246.0 秒；在 150 艘船算例上，Gurobi 在 3600 秒时限内平均间隙为 6.8%，本文算法在 420 秒内将间隙收窄至 0.9%。到港方差扩大至基准值的 1.5 倍时，总成本增幅保持在 3.2% 以内（图 6）。

### 样例 4：防误报保留（Z5 + Z6 命中但应判「留」）

- **原稿**：求解组合优化问题的常见途径包括整数规划、动态规划与近似算法。本文提出的列生成算法包含以下三步：首先，用贪心启发式生成初始可行航线集；其次，求解线性松弛主问题获取对偶乘子；最后，在时空网络上用标号算法求解定价子问题。
- **判定**：**留（KEEP）**。「整数规划、动态规划与近似算法」是标准学科分类名词，不是公文四字格堆砌；「首先/其次/最后」对应列生成算法的严格迭代步骤，删改反而损害可读性。
