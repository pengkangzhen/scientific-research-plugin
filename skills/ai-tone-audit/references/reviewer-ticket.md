# Stage 2 独立上下文审稿工单契约（Reviewer Ticket）

## 为什么要隔离上下文

刚写完或润色完某段文字的模型，会对自己刚生成的过渡词、对称句式和套话产生上下文盲区（自我合理化）。因此 Stage 2 优先派发给**未参与该手稿起草的独立子智能体**执行：它不继承主会话的写作意图辩解，只看手稿原文、Stage 1 扫描结果和 `references/tells.md` 判准。

## 报告怎么交付（主会话与子智能体的分工）

- **子智能体不写文件**：它在只读沙箱里运行，写出的文件会落进它自己的临时目录，用户在项目里找不到。它把**完整报告作为回复正文**返回。
- **主会话负责落盘与呈现**：收到报告后，主会话 ① 用 `write_file` 把报告存进项目 `paper/audit/`（无 `paper/` 目录则存手稿所在目录的同级 `audit/`），文件名 `ai-tone_<手稿名>_L<起>-<止>.md`（全稿审计省略行号段）；② 在对话里**把条目卡完整贴出来**，并写出报告文件的**绝对路径**。Stage 1 的 `scan.json` / `scan.md` 属于一次性中间产物，放 `/tmp`，不进项目。
- 不得把报告写进 harness 的私有产物目录（如 `.gemini/.../brain/`、`.claude/` 缓存）后只报文件名。

## 派工工单模板

向子智能体（`research` 只读审计子智能体，或通用只读子智能体）发送如下工单：

```markdown
角色：你是中文学术手稿「去 AI 味」独立审计员，未参与被审稿件的写作。
任务：基于 Stage 1 确定性扫描报告与分类细则，对指定手稿执行只读 AI 腔审计。

输入材料：
1. 待审手稿路径：<绝对路径>（审计范围：<全稿 / 指定章节名或行号区间>；找事实时要检索整篇手稿，不限于审计范围）
2. Stage 1 扫描 JSON/Markdown 路径：<scan.md 或 scan.json 绝对路径>
3. 判定准则路径：<.../skills/ai-tone-audit/references/tells.md>

审计要求：
1. 先看分章节密度表，优先精读密度等级为「高」「中」的章节；密度为「低」的章节也须通读一遍，捞出确定性规则抓不到的 Z10（无数据空泛断言）与逻辑空转段（「车轱辘话」重复同义句）。
2. 对 Stage 1 的每一处非豁免命中，读取手稿前后 2–3 句上下文：
   - 属于标准术语枚举（Z5）、算法/证明步骤枚举（Z6）、定义节规整句式（Z12）、章末小结正常收束（Z2/Z7）→ 判「留（KEEP）」并写清理由。
   - 属于对冲词堆叠或 Results 免责退路 → 判「转 hedge-audit」；属于可疑自造复合术语 → 判「转 term-audit」。
   - 确认属实的 AI 腔 → 按 tells.md 判「删 / 实 / 改」，并**写出改后的完整文本**。
3. 事实只取自手稿，且不向用户要数据：
   - 判「实」时，在整篇手稿（含 \input 展开的全部章节、表格、图注）里检索对应的数字、算例、方法细节，找到就写进改后文本并标出处（「表 4」「§5.2」）。
   - 全稿检索后仍无支撑的断言，说明原句本就是无据空话：整句删除，或降格为只依据手稿已有结果的条件式/定性表述。严禁编造数字、比例、文献，严禁在改后文本里留 `⟨作者补⟩` 之类占位符，严禁以「请作者补充」为由搁置某一条。
   - 无支撑而被删/降格的条目，在「病因」栏注明「全稿无支撑」。
4. 严禁同义词替换式改法（如把「至关重要」改成「极为关键」）。
5. 全程只读：不得修改任何手稿文件，也不要写任何文件；完整报告作为回复正文返回。

输出格式（严格按以下四节）：

### 1. 总结论与重灾区定位
一句话概括审计范围内 AI 腔程度、最重章节及主导病因（如"§5.4 与 §6 套话密集，主因是三段模板同构与无据断言；§5.1 模型设定干净"），并给出统计：命中 N 处、判改 a 处、判留 b 处、转交 c 处。

### 2. 逐条改写清单（核心交付，按手稿行号升序）
每处问题一张条目卡，四项缺一不可：

**#1** · `main.tex:707-708` · 类别 Z6
- **原句**：手稿原文，完整引出（多句成段时整段引出）
- **病因**：类别编号 + 一句话说明为什么读起来像 AI，点出具体的词或句型（不写「AI 味重」这类空评价）
- **改法**：处置（删/实/改）+ 具体做了什么；有取自手稿他处的事实时注明出处
- **改后**：可直接替换的完整文本，LaTeX 命令、`\cite`、`\ref`、公式原样保留

判「留」「转」的条目也用同样的卡片：「改后」写「不改」，「改法」写理由或转交对象。

### 3. 确定性扫描漏网项（LLM 补充检出）
正则未命中但通读发现的空心段落、同义车轱辘话、缺乏主语或具体对象的泛泛之谈，同样用条目卡呈现，接在第 2 节编号之后。

### 4. 保留项与转交项汇总
- **保留（KEEP）**：位置 + 命中词 + 放行理由（防误报复核）
- **转交（ROUTE）**：建议交 `hedge-audit` 或 `term-audit` 的位置清单
```

## 长稿切批策略

当审计范围超过 15,000 字（如硕博学位论文全文）或非豁免命中超过 80 处时，不要塞进单个子智能体上下文（避免后半程注意力衰减沦为机械抄表）：

- 按章（`\chapter` / 一级标题）切分为 2–4 个并行只读审计工单，每个工单附该章对应的扫描切片，且都要能检索整篇手稿找事实；
- 主会话汇总各章条目卡，统一重新编号后输出一份审计报告。
