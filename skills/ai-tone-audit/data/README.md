# data/ — ai-tone-audit 规则库与基线说明

| 文件 | 入库状态 | 生成/维护方式 | 用途 |
|---|---|---|---|
| `rules_zh.jsonl` | 入库 | 人工维护（每行一条 JSON 规则） | Stage 1 中文 AI 腔确定性初筛规则集（Z1–Z11 + R 转交规则） |
| `baseline_stats_zh.json` | 可选本地生成 | `scripts/build_baseline.py` | ≤2022 人类中文学术语料的经验分布（均值/分位数/句长 CV），自动替代暂定阈值 |

## `rules_zh.jsonl` 字段约定

每行一个 JSON 对象：

- `id`：规则编号（如 `Z1-01`、`R-01`）
- `cat`：病理大类（`Z1`–`Z11`，`R` 为转交类，`Z12` 由脚本统计层产出）
- `w`：加权分（`0` 表示仅提示或转交，不计入 AI 腔密度分；高频连接词取 `0.5` 只看聚集密度）
- `scope`：匹配粒度
  - `span`：段落全文 `finditer`
  - `sent`：逐句锚定句首匹配
  - `last`：仅匹配多句段落（≥2 句）的最后一句
  - `nodigit`：逐句匹配，且该句不含阿拉伯数字、百分号或公式占位符时才命中
  - `stack2`：同一句内命中 ≥2 次才记一条（如认识论对冲词堆叠）
- `pattern`：Python 正则表达式
- `exempt`：章节标题豁免正则（如 `"小结|结论|总结"`——章末小结中的「综上所述」记为豁免、权重归零）
- `note`：规则简述

## 规则来源

综合以下公开证据与中文学术审稿共识整理（详见 `docs/research/`）：

1. Wikipedia WikiProject AI Cleanup（`WP:AISIGNS`）：否定式平行、三段式枚举、拔高意义、段末升华、破折号与粗体排版癖；核心判准为**看聚集密度而非禁用单词**。
2. Chakrabarty, Laban & Wu（CHI 2025, LAMP 语料）：专业编辑修订归纳的陈词滥调、冗余解释、缺乏具体性（对应 `Z10` 无数字评价断言）。
3. Reinhart et al.（*PNAS* 2025）与翻译学「翻译共性」（显化、规范化）：映射至中文欧化弱动词（`对……进行分析`、`得到了……验证`）、无主语使字句（`通过……使得……`）与路标词过密。
4. 中文开源社区（`Humanizer-zh` 等）与中文核心期刊/学位论文审稿常见病：宏大背景铺垫壳、公文/营销热词（赋能/闭环/抓手/全方位）、四字格连排。

## 人类基线构建与版权口径

中文核心期刊（知网/万方系）全文不在公开 API 中分发；OpenAlex 仅少量中文 OA 期刊（如《软件学报》《自动化学报》部分年份）带中文摘要，且摘要密度不等同于正文章节密度。因此推荐课题组用本地 **2022 年及以前** 的中文论文全文或往届学位论文生成基线：

```bash
uv run skills/ai-tone-audit/scripts/build_baseline.py \
  --corpus "published_le2022/*.tex" "theses_le2022/*.docx" \
  --desc "课题组 ≤2022 中文论文全文" \
  --out skills/ai-tone-audit/data/baseline_stats_zh.json
```

`baseline_stats_zh.json` **只保存汇总统计量**（篇数、字数、加权分分位数、句长变异系数分位数、各类别每千字命中率），不保存任何原文片段，可安全入库或随课题组共享。
